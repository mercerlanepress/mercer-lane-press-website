A tidy archive is not automatically a useful archive.

The practical test is whether an authorized household member can locate the current record when it is needed without opening several apps, searching old messages, or asking the one person who usually knows where everything is.

Build the system around retrieval rather than perfect classification.

## Use broad categories the household already understands

Start with ordinary household language.

Useful categories may include:

- home or housing;
- vehicles;
- school or childcare;
- health logistics;
- insurance;
- tax;
- travel;
- pets;
- identification;
- warranties and service records.

Do not create deep folder trees unless a category genuinely becomes crowded. A shallow structure is easier to navigate when somebody is under pressure or did not design the system.

## Index the location, not every document

A household document index should answer one question:

**Where would I find this?**

It does not need to reproduce the contents of every file or folder.

For a physical record, use a path another person can follow. “Insurance folder” may be too vague. A more useful description identifies the actual storage place and the relevant section.

For a digital record, identify the service and folder path rather than writing only “online” or “in email.”

If access requires a separate secure method, the index can point to that approved route without copying the credential into the household workbook.

## Keep the working index low-risk

Convenience can turn an ordinary binder or spreadsheet into a concentration of sensitive information.

Use the minimum detail needed to identify and retrieve the authoritative record.

The household system should generally avoid storing passwords, PINs, recovery codes, full financial credentials, and unnecessary identity numbers on everyday tracking pages. Keep sensitive material in appropriate secure storage and let the index point to that location.

The same principle applies to old exports and screenshots. Extra copies can become stale and can increase unnecessary exposure.

## Distinguish current records from archives

Multiple copies create a version-control problem.

If several documents look current, another household member may choose the wrong one.

Where practical:

- choose one authoritative current location;
- separate current records from archives;
- label older material clearly when it must be retained;
- remove unnecessary duplicates appropriately;
- update the location index whenever a current record moves.

A move to a new folder or service is not complete until the retrieval map points to the new location.

## Use clear digital filenames

Consistent filenames can improve scanning and search without adding more folder levels.

One practical pattern is:

**YYYY-MM-DD – provider – subject**

The date supports sorting. Provider and subject make the file easier to recognize in search results.

The exact naming scheme matters less than using one that the household can understand later.

## Do not invent universal retention periods

Different records can have different requirements depending on jurisdiction, document type, legal context, tax position, property status, insurance circumstances, and other factors.

If a retention period matters, check current official guidance or an appropriately qualified professional before disposing of the record.

The family admin system can record:

- what the record is;
- why it is being kept;
- where it lives;
- when it should be reviewed.

It should not guess a universal “keep for X years” rule.

## Run a no-coaching retrieval test

Choose three ordinary records and ask another authorized household member to find them using only the index.

Do not explain what your labels mean while they search.

Notice where they hesitate:

- ambiguous folder names;
- several copies that look current;
- a path that says only “cloud” or “email”;
- private shorthand;
- access that works only for the usual administrator.

Fix the system rather than coaching the person through it.

The aim is predictable retrieval, not a museum-quality filing system.

## Make the index part of continuity planning

A document-location index is one of the core controls in the [minimum viable family admin system](/family-admin/how-to-organize-family-admin/).

It becomes even more useful during the [Household Handover Test](/family-admin/household-handover-test/), when another trusted adult tries to operate the next week without relying on the usual administrator’s private memory.

If they can find the calendar but not the supporting record, the household still has a single point of failure.
